# FCPKit v0.1.0 — First Working Version

> **Status: proposal, not accepted.** This is a design document saved for further analysis. No
> implementation work has started. Findings marked "confirmed" below were verified against the
> checked-in fixtures and the Final Cut Pro 1.14 DTD; design choices are proposals open to
> revision.

## Context

FCPKit aims to be the Swift foundation for apps that create, modify, and read Final Cut Pro
assets. The `v0.1.x` branch already carries a working XMLCoder-backed Codable model (~80 types,
~2250 lines), a structural diff/DTD-validation harness, and real 1.13/1.14 fixtures reporting zero
round-trip loss.

Three things block calling it a first working version:

1. **The spine mis-orders on round-trip — confirmed, not theoretical.** `Spine`
   (`Sources/FCPKit/FCPXML.swift:297`) stores children as 14 parallel arrays with `assetClips`
   declared before `transitions` in `CodingKeys`. The DTD says
   `<!ELEMENT spine (%clip_item; | transition)*>` — one ordered heterogeneous sequence. The real
   fixture `Tests/FCPKitTests/FeaturePairs/transitions/after.fcpxml:49-62` is
   `asset-clip, transition, asset-clip`; decode buckets it into two arrays and re-encode emits
   `asset-clip, asset-clip, transition`. That is a different cut, and Final Cut rejects it.
   The schema-completeness gate reads 0 because `Inventory`
   (`Sources/FCPXMLDiff/FCPXMLDiffEngine.swift:186-207`) keys a multiset by ancestor path with no
   sibling ordering, so counts match before and after. **The "0 dropped elements" baseline is real
   but order-blind.**
2. **Every model field is `String?`** — times, ints, bools, IDs, refs alike. `"1001/30000s"` and
   `"1920"` and `"1"` are all just strings, so nothing is checked and arithmetic is ad-hoc.
   `AssetClipEditing.formatSeconds` already emits `13.333333333333334s` for non-integral speeds.
3. **There is no authoring API.** Constructing a document means nesting ~15 initializers with
   hand-written `"r1"`/`"r2"` id strings; a typo produces a dangling ref that fails at FCP import.

v0.1.0 delivers: correct ordered content, strong value types, and a resultBuilder DSL for
authoring a real cut — plus an optional read-only ScriptingBridge inspector.

## Verified findings that shape the design

**XMLCoder preserves child order; no fork needed.** `KeyedBox.elements` is `KeyedStorage`, an
insertion-ordered `[(Key, Value)]` buffer; `formatXMLElements` iterates without sorting. Sorting
happens only in `formatSortedXMLElements`, reached only when `.sortedKeys` is set — and
`FCPXMLParser` sets only `.prettyPrinted`. So child element order equals `CodingKeys` order.
`XMLChoiceCodingKey` + `ChoiceBox` handle ordered heterogeneous children in both directions.
Step 0 pins both behaviors with tests so a future XMLCoder bump fails loudly rather than silently
emitting FCP-rejected files.

**Final Cut's AppleScript dictionary is read-only.** `ProEditor.sdef` exposes
`application → libraries → events → projects/sequences` with a single `get` command, every class
marked `access="r"`. There is no export, import, or mutation command — which corroborates
`AGENTS.md`'s note that AppleScript cannot automate exports. The ScriptingBridge target is
therefore an inspector, not an automation layer.

**`audioRate` has two value spaces.** `asset.audioRate` is `"48000"`; `sequence.audioRate` is
`"48k"` (DTD `%audioHz;`). `Asset.audioRate` becomes `Int`; only `Sequence`/`Multicam` use the
`AudioRate` enum. Reversing this breaks all four fixtures.

## Decisions

- Work on `v0.1.x`, evolving the existing code. No rewrite.
- Strong types in the Codable model itself, not only in a DSL layer.
- Ordered spine lands **first**, as a clean break — no `assetClips` compatibility shims. All test
  call sites move to the new `items` API in the same PR.
- DSL covers document → spine story items, with the builder protocol shaped so multicam,
  sync-clip, and nested spines slot in later without redesign.
- Resource IDs auto-assign `r1..rN` from typed handles, with per-resource manual override.
- ScriptingBridge is an additive, macOS-only, read-only target.

## 1. Strong types

One protocol plus shared Codable extensions — not property wrappers, which would break
`DynamicNodeEncoding` (it dispatches on the *key*) and force `@Wrapper` at every use site.

```swift
public protocol XMLAttributeValue: Codable, Hashable, Sendable, LosslessStringConvertible {
    init?(fcpxmlString: String)
    var fcpxmlString: String { get }
}

public extension XMLAttributeValue {
    init?(_ description: String) { self.init(fcpxmlString: description) }
    var description: String { fcpxmlString }

    init(from decoder: Decoder) throws {
        let raw = try decoder.singleValueContainer().decode(String.self)
        guard let value = Self(fcpxmlString: raw) else {
            throw DecodingError.dataCorrupted(.init(
                codingPath: decoder.codingPath,
                debugDescription: "Invalid \(Self.self) value: \(raw)"))
        }
        self = value
    }

    func encode(to encoder: Encoder) throws {
        var c = encoder.singleValueContainer()
        try c.encode(fcpxmlString)
    }
}
```

Every conformer encodes as a single-value `String`, so XMLCoder sees exactly what it sees today
and `FCPXMLNodeEncoding.swift` needs no changes beyond `Spine`.

### FCPTime — canonical-form preservation

Round-trip must be byte-stable: `"5s"` must not become `"5/1s"`, and `"1001/30000s"` must not
reduce. The rule: **store numerator/denominator as written, plus how it was written. Never
renormalize on decode.** Only newly constructed values pick a form.

```swift
public struct FCPTime: XMLAttributeValue, Comparable {
    public enum Form: Hashable, Sendable { case whole, rational }

    public let numerator: Int64
    public let denominator: Int32   // invariant: > 0
    public let form: Form

    public static let zero = FCPTime(numerator: 0, denominator: 1, form: .whole)

    public init(numerator: Int64, denominator: Int32 = 1, form: Form? = nil)
    public init?(fcpxmlString raw: String)      // "5s" → .whole; "1001/30000s" → .rational
    public var fcpxmlString: String             // renders per `form`
    public var seconds: Double

    public static func frames(_ count: Int64, at frameDuration: FCPTime) -> FCPTime
}
```

Three consequences to implement explicitly:

- **`form` must not participate in equality.** `"5s"` and `"5/1s"` are the same instant. Write
  `==` cross-multiplying in `Int64` with overflow check, and hash the reduced fraction, so `form`
  stays a rendering hint. Add `isIdenticallyFormatted(to:)` for the byte-stability test.
- **Never reduce.** `"22800/2400s"` stays as written. The completeness gate compares attribute
  values as strings, so reduction would register as `changedAttribute`. Reduction is opt-in via
  an explicit `reduced()`.
- **Arithmetic picks `.rational`** with an LCM common denominator (`Int32` overflow-checked,
  throwing `FCPXMLError`). This lets `AssetClipEditing.formatSeconds` be deleted outright:
  `setConstantSpeed(percent: 75, mediaDuration: "10s")` becomes exactly `40/3s`, not
  `13.333333333333334s`. **This is a real behavior fix and needs its own regression test.**

### Bool, enums, IDs

`FCPBool` maps `"1"`/`"0"` and is `ExpressibleByBooleanLiteral`. Enums get the conformance nearly
free:

```swift
public extension XMLAttributeValue where Self: RawRepresentable, Self.RawValue == String {
    init?(fcpxmlString raw: String) { self.init(rawValue: raw) }
    var fcpxmlString: String { rawValue }
}

public enum TCFormat: String, XMLAttributeValue { case df = "DF", ndf = "NDF" }
public enum AudioLayout: String, XMLAttributeValue { case mono, stereo, surround }
public enum ColorProcessing: String, XMLAttributeValue { case standard, wide, wideHDR = "wide-hdr" }
```

**Enums must not be closed to unknown input.** `colorSpace`, `renderFormat`, roles and
`fieldOrder` are `CDATA`; even true enumerations gain cases across versions. Decode must
preserve-and-pass-through rather than throw, per ADR 0001's best-effort policy. Pin this with a
test feeding an out-of-vocabulary value.

`ResourceRef<Kind>` is phantom-typed (`AssetKind`, `FormatKind`, `EffectKind`, `MediaKind`) so
`AssetClip.ref` can't take a format id. This is **advisory in the model** — decode accepts any
string, since the DTD only says `IDREF` and real files must still load — and **enforced in the
builder**, where handles are typed.

## 2. Ordered content models

```swift
public enum SpineItem: Hashable, Sendable {
    case assetClip(AssetClip), clip(Clip), gap(Gap), title(Title)
    case video(Video), audio(Audio), refClip(RefClip)
    case syncClip(SyncClip), mcClip(MCClip), transition(Transition)

    enum CodingKeys: String, XMLChoiceCodingKey {
        case assetClip = "asset-clip"
        case clip, gap, title, video, audio
        case refClip = "ref-clip", syncClip = "sync-clip", mcClip = "mc-clip"
        case transition
    }
}
```

Decode dispatches on `container.contains(_:)` — **not** try/catch chaining, which is O(n) and
masks genuine decode errors inside a matched child as "try the next case."

`Spine` collapses from 14 arrays to:

```swift
public struct Spine: Codable, Hashable, Sendable {
    public var lane: Int?
    public var offset: FCPTime?
    public var name: String?
    public var format: ResourceRef<FormatKind>?
    public var items: [SpineItem]

    enum CodingKeys: String, CodingKey { case lane, offset, name, format, items = "" }
}
```

`items = ""` places the choice array as inline children; `Spine`'s `DynamicNodeEncoding` returns
`.element` for `""` and `.attribute` for the four attributes. **Spike this on day one** (Step 0).
If `""` plus choice-array doesn't compose, the fallback is a hand-written `encode(to:)` that
encodes attributes into a keyed container then loops `items` through the choice container — the
`MixedEitherSide` pattern, already proven in XMLCoder's own tests.

`AnchoredItem` is the same shape for `%anchor_item;`, minus `gap`/`transition`, plus `spine` —
that is how connected storylines nest.

**Ordering within an element** comes from `CodingKeys` declaration order, transcribed from the
DTD. Today's `AssetClip.CodingKeys` puts `keyword` before `note` and `adjust-volume` before
`audio-channel-source`, where the DTD (line 516) mandates
`note?, conform-rate?, timeMap?, %intrinsic-params;, (%anchor_item;)*, (%marker_item;)*,
audio-channel-source*, (%video_filter_item;)*, filter-audio*, metadata?`. Reordering `CodingKeys`
to DTD order is a required fix that the completeness gate cannot see. Comment each `CodingKeys`
block with its DTD line number.

## 3. resultBuilder DSL

```swift
public protocol SpineContent {
    func resolve(into ctx: inout BuildContext) throws -> [SpineItem]
}
public protocol AnchoredContent {
    func resolve(into ctx: inout BuildContext) throws -> [AnchoredItem]
}
```

`resolve` returns a plural so one DSL node can expand to several elements later (audition,
compound expansion). `BuildContext` carries the `ResourceTable` and enclosing format, so children
inherit frame duration for `.frames(_:at:)`.

```swift
@resultBuilder public enum SpineBuilder {
    public static func buildBlock(_ parts: [any SpineContent]...) -> [any SpineContent]
    public static func buildExpression(_ e: any SpineContent) -> [any SpineContent]
    public static func buildOptional(_ c: [any SpineContent]?) -> [any SpineContent]
    public static func buildEither(first c: [any SpineContent]) -> [any SpineContent]
    public static func buildEither(second c: [any SpineContent]) -> [any SpineContent]
    public static func buildArray(_ c: [[any SpineContent]]) -> [any SpineContent]
    public static func buildLimitedAvailability(_ c: [any SpineContent]) -> [any SpineContent]
}
```

Parallel builders: `AnchoredBuilder`, `ResourcesBuilder`, `EventBuilder`, `LibraryBuilder`.
`for`/`if` support comes free from `buildArray`/`buildOptional` — which matters for programmatic
cuts.

Representative elements:

```swift
public struct AssetClipItem: SpineContent {
    public init(_ asset: AssetHandle, name: String? = nil,
                offset: FCPTime? = nil, duration: FCPTime? = nil,
                start: FCPTime? = nil, lane: Int? = nil, audioRole: String? = nil,
                @AnchoredBuilder anchored: () -> [any AnchoredContent] = { [] })
}

public struct TransitionItem: SpineContent {
    // DTD line 613: transition has ONLY name/offset/duration —
    // no ref, lane, start, or enabled. Deliberately absent below.
    public init(_ effect: EffectHandle, name: String? = nil,
                offset: FCPTime? = nil, duration: FCPTime,   // #REQUIRED
                audioEffect: EffectHandle? = nil)
}

public struct NestedSpine: SpineContent, AnchoredContent {
    public init(lane: Int? = nil, offset: FCPTime? = nil,
                @SpineBuilder _ items: () -> [any SpineContent])
}
```

`duration` is non-optional on `TransitionItem`/`GapItem` (DTD `#REQUIRED`) and optional on
`AssetClipItem` (`%clip_attrs_with_optional_duration;`). The type system carries DTD requiredness
directly — the highest-value part of strong typing for authoring.

## 4. Resource IDs

Reference-typed handles plus a two-pass build.

```swift
public final class AssetHandle: Hashable, Sendable {
    public init(_ spec: AssetSpec, id: ResourceID? = nil)
    public static func == (l: AssetHandle, r: AssetHandle) -> Bool { l === r }
}
```

Identity is `ObjectIdentifier` on a `final class`. This makes dangling refs **unrepresentable**:
referencing an asset requires holding its handle, and the DSL surface exposes no
`ResourceRef("r7")` path.

1. **Collect.** Walk the tree; each `resolve` touching a handle calls `intern`. First touch
   appends to an ordered list and reserves an id. Manual overrides (`AssetHandle(spec, id: "r42")`)
   are claimed *before* auto-assignment begins, so the counter skips them. Duplicate manual id
   throws `BuildError.duplicateResourceID`. A handle interned twice returns the same id, so dedup
   is free.
2. **Materialize.** `Resources` is built in first-reference order, matching how FCP writes files
   and keeping the normalizer's first-appearance mapping stable. Do **not** topologically sort —
   the transitions fixture declares asset `r5` before its own format `r6`, so real FCP output
   isn't sorted either.

Unused resources are a warning, not an error; FCP emits unused formats.

## 6. Sequencing

Each step ends green on `swift test` **and**
`swift run fcpxml-diff schema-completeness Tests/FCPKitTests/TestData --fail-if-total-exceeds 0`.
The gate is order-blind, so Step 0's order tests are what actually protect Steps 3–5.

**Step 0 — guardrails, no model change.** `EncoderOrderingTests` (a struct with `CodingKeys b, a`
emits `<b/><a/>`) pins XMLCoder's ordering. `ChoiceEncodingSpike` proves a choice array
round-trips in order inside an element that also has attributes. `SpineOrderTests` asserts the
transitions fixture's spine is `asset-clip, transition, asset-clip` as a raw XML tree — **this
fails today**; mark `XCTExpectFailure` and flip it in Step 3. Blast radius: zero.

**Step 1 — value types, unused.** All of `Sources/FCPKit/Values/` plus unit tests: `FCPTime`
parses and re-emits `"5s"`, `"0s"`, `"1001/30000s"`, `"22800/2400s"` byte-identically; rejects
`"5"`, `"5/0s"`, `""`; arithmetic is exact. Nothing references them yet. Blast radius: zero.

**Step 2 — leaf types, one PR each.** `Timept`, `Marker`, `ChapterMarker`, `Keyword`, `Rating`,
`ConformRate`, `Fade`, `Keyframe`, `MediaRep`, `TrimRect`. Nothing embeds these except as arrays.
~5–15 call sites each, all in tests. `AssetClipEditing.addMarker`/`setConstantSpeed` signatures
change here and **`formatSeconds` is deleted**, fixing the `13.333…s` bug.

**Step 3 — `Spine` → ordered `items` (the risky one, land alone).** Introduce `SpineItem`,
rewrite `Spine`, flip the Step 0 expected-failure. Clean break, no shims: ~25 call sites across
`FeaturePairTests`, `RealFCPXMLTests`, `FCPKitTests` move from `spine?.assetClips?.first` to
pattern-matching over `items`. Review carefully.

**Step 4 — story elements.** `AssetClip`, `Title`, `Transition`, `Gap`, `RefClip`, `Video`,
`Clip`, `SyncClip`, `MCClip`: typed values **and** `CodingKeys` reordered to DTD order with line
comments. `AnchoredItem` lands here (the titles fixture's `title` nested inside `asset-clip`).
`MulticamXMLBuilder` is the biggest non-test consumer and needs a mechanical sweep in the same PR.

**Step 5 — resources + document.** `Asset`, `Format`, `Effect`, `Media`, `Multicam`, `MCAngle`,
`Resources`, `Library`, `Event`, `Project`, `Sequence`. `ResourceID`/`ResourceRef` land. Watch the
`audioRate` split.

**Step 6 — `FCPKitBuilder`.** Purely additive; nothing in `FCPKit` changes.

**Step 7 — `FCPKitScripting`.** Purely additive, macOS-only.

**Step 8 — docs.** ADR 0002 (ordered content + typed values, and the explicit note that the
completeness gate is order-blind). Update `AGENTS.md` — including its incorrect claim that the
stack is Swift Testing — plus `docs/NEXT_STEPS.md` and `README.md`.

Steps 1, 2, 6, 7 are individually safe. Step 3 is the risky one. Steps 4–5 are large but
mechanical.

**Narrower alternative if 0.1.0 should ship sooner:** Steps 0–3 plus 6 (correct ordering + DSL),
deferring the full String→typed sweep in Steps 4–5 to 0.1.1.

## 7. ScriptingBridge inspector

macOS-only, read-only, mirroring exactly what `ProEditor.sdef` offers:

```swift
public struct FCPLibraryInspector: Sendable {
    public static func isFinalCutRunning() -> Bool
    public func libraries() throws -> [FCPScriptedLibrary]   // name, id, persistentID, fileURL
}

public struct FCPScriptedLibrary: Sendable {
    public var events: [FCPScriptedEvent]                    // → projects, sequences
}

public struct FCPScriptedSequence: Sendable {
    public var name: String
    public var duration: FCPTime        // from the sdef `media time` record (value/timescale)
    public var frameDuration: FCPTime
    public var timecodeFormat: TCFormat
}
```

Bridging notes: the sdef's `media time` record is `{value, timescale, epoch, flags}` — map
`value`/`timescale` onto `FCPTime` so scripted and XML times share one type. Prefer a hand-written
protocol layer over raw `SBObject` so the API is testable without FCP running;
`isFinalCutRunning()` gates every call and tests skip when absent. Requires
`NSAppleEventsUsageDescription` and the `com.apple.security.automation.apple-events` entitlement
in consuming apps — document this in the README.

Explicitly **not** in scope: driving File → Export XML via System Events keystrokes. It is
fragile across FCP versions and localizations.

## 8. Testing

Existing gates stay: `swift test`, completeness at 0, `fcpxml-diff validate`.

New:

- **Order tests** (permanent). Raw-tree sibling-order assertions on all five FeaturePairs
  `after.fcpxml`, decoded → re-encoded. This is precisely the gap the completeness gate cannot
  see, so it must exist as its own test.
- **Byte-stability tests.** Per fixture: decode → encode → assert every `%time;` attribute string
  is character-identical to source. Catches accidental `5s` → `5/1s` or reduction.
- **DSL correctness — the strongest signal.** For each FeaturePair, hand-write the DSL that should
  reproduce `after.fcpxml`, then DSL → encode → **`xmllint` DTD-validate against
  `FCPXMLv1_14.dtd`** → decode → normalize with the existing `FCPXMLNormalizer` (which already
  neutralizes `r1..rN`, `uid`, `sig`, `modDate`, bookmarks) → structural-equal the normalized
  fixture. Reusing the normalizer is what makes the comparison tractable. Gate on `transitions`
  and `titles` at minimum — together they exercise ordering, nested anchored items, and effect
  refs.
- **DTD validation of DSL output must be a hard failure.** Existing `DTDValidationTests` skip when
  FCP isn't installed; keep that for fixtures, but add an opt-in `FCPKIT_REQUIRE_DTD=1` that turns
  skip into failure for the authoring path.
- **Builder invariants.** Duplicate manual id throws; the same handle referenced twice yields one
  resource; manual `r42` doesn't collide with auto-assignment; declaration order preserved.
- `testEveryModelTypeDeclaresNodeEncoding` extends to `SpineItem`/`AnchoredItem`.

DTD source:
`/Applications/Final Cut Pro Creator Studio.app/Contents/Frameworks/Interchange.framework/Versions/A/Resources/FCPXMLv1_14.dtd`
(lines 435, 476, 516, 566, 613 are the content models to transcribe).

**XCTest vs swift-testing: later, not now.** All 9 test files are XCTest despite AGENTS.md's
claim. Migrating touches every file the migration steps touch, which would make Step 3's diff
unreviewable and destroy bisectability. Land 0.1.0 on XCTest, write new tests in XCTest too
(mixing mid-migration is worse than either), then migrate wholesale in 0.1.1 as a single
no-behavior-change PR. Fix the AGENTS.md claim in Step 8.

## 9. Risks

| Risk | Mitigation |
| --- | --- |
| Choice-array + attributes on `Spine` doesn't compose in XMLCoder | Step 0 spike before any model change; fallback is hand-written `encode(to:)` (`MixedEitherSide`, already proven) |
| **Completeness gate stays green through an ordering regression** | Explicit order tests; record in ADR 0002 that the gate is order-blind |
| Closed enums throw on unseen real-world values | Preserve-and-pass-through + out-of-vocabulary decode test |
| `audioRate` value-space split (48000 vs 48k) | Called out in Step 5; fixture tests catch it |
| Step 3 blast radius stalls the branch | Land alone, review carefully; no shims per decision |
| `Int32` overflow in `FCPTime` LCM arithmetic | Overflow-checked ops throwing `FCPXMLError`, with a boundary test |
| No FCP import gate for DSL output | Explicit non-goal; add a "ready for human" entry to `docs/manual/typed-generation-gate.md` |

## Non-goals for 0.1.0

Sidecar preservation of unknown XML (ADR 0001 stands); `audition`, `live-drawing`,
`object-tracker`, masks, 360/stereo adjustments; smart-collection authoring via DSL; timeline
math (auto-computing offsets from durations); AppleScript-driven export automation; an FCP
import round-trip gate for DSL output (needs a human); XCTest → swift-testing migration; CI.
