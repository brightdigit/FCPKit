## 1. The spine ordering bug (CONFIRMED — highest priority)

### Evidence

`Tests/FCPKitTests/FeaturePairs/transitions/after.fcpxml`, lines 49-62:

```
49:  <spine>
50:      <asset-clip ref="r2" offset="0s" name="Left" duration="22800/2400s" tcFormat="NDF" audioRole="dialogue"/>
51:      <transition name="Cross Dissolve" offset="9s" duration="1s">
61:      <asset-clip ref="r5" offset="22800/2400s" name="Right" start="1200/2400s" duration="20400/2400s" format="r6" tcFormat="NDF" audioRole="dialogue"/>
62:  </spine>
```

Order on disk: `asset-clip, transition, asset-clip`.

`Sources/FCPKit/FCPXML.swift:297` — `Spine` stores 14 parallel optional arrays. Its `CodingKeys`
declares `assetClips = "asset-clip"` **before** `transitions = "transition"`. Since XMLCoder emits
child elements in `CodingKeys` order (see §2), decode-then-encode produces:

```
asset-clip, asset-clip, transition
```

That is a different cut. Final Cut rejects it — a transition must sit between the two clips it
joins.

The DTD (`FCPXMLv1_14.dtd`) declares:

```
<!ELEMENT spine (%clip_item; | transition)*>
```

One ordered heterogeneous sequence, not fourteen independent collections.

### Why the existing gate does not catch it

`Sources/FCPXMLDiff/FCPXMLDiffEngine.swift:186-207` — `Inventory` builds a **multiset keyed by
ancestor path**, with no sibling ordering:

```
/fcpxml/library/event/project/sequence/spine/asset-clip → 2
/fcpxml/library/event/project/sequence/spine/transition → 1
```

Identical before and after reordering, so the report shows zero loss. The documented baseline in
`docs/NEXT_STEPS.md` ("4 files, 0 dropped elements / 0 attributes / 0 text / 0 total") is
**genuine but order-blind**. It is not evidence that round-tripping is safe.

`FeaturePairTests` also passes, because it asserts through `spine?.assetClips?.first` — an
accessor that cannot observe sibling order.

**Implication:** any fix needs its own order tests. Extending the completeness gate would be an
alternative, but changing the diff engine's matching semantics risks masking real differences
elsewhere; a separate raw-tree order assertion is narrower and safer.

## 2. XMLCoder behavior (VERIFIED — no fork needed)

### Child element order follows `CodingKeys` order

Mechanism, traced through XMLCoder 0.17.1:

- `KeyedBox.elements` is `KeyedStorage`, an insertion-ordered `[(Key, Value)]` buffer
  (`KeyedStorage.swift:10-49`).
- `XMLCoderElement.init(key:isStringBoxCDATA:box:)` iterates that buffer in order
  (`XMLCoderElement.swift:372+`).
- `formatXMLElements` iterates without sorting (`XMLCoderElement.swift:233-250`).
- Sorting happens **only** in `formatSortedXMLElements` (line 214), reached only when
  `.sortedKeys` is set.

`FCPXMLParser.encode` (`Sources/FCPKit/FCPXMLParser.swift`) sets only `.prettyPrinted`. So
`CodingKeys` declaration order is the emitted element order.

**This is load-bearing and undefended.** A future XMLCoder bump that adds sorting would silently
produce FCP-rejected files. Hence the proposed `EncoderOrderingTests` guardrail.

### Ordered heterogeneous children are already supported

`XMLChoiceCodingKey` + `ChoiceBox` handle this in both directions. Confirmed against XMLCoder's
own test suite:

- `NestedChoiceArrayTest` — decodes `intro, chapter, chapter, outro` in order.
- `CompositeChoiceTests.testEncodeArrayOfIntOrStringWrappers` — encodes an array of choices.
- `MixedChoiceAndNonChoiceTests.MixedEitherSide` — proves leading/choice/trailing order survives
  encode.

That last one is the fallback pattern if `items = ""` plus a choice array doesn't compose on an
element that also carries attributes.

**Decode dispatch note:** prefer `container.contains(_:)` over try/catch chaining.
`NestedChoiceArrayTest` uses chaining, but it is O(n) and — worse — swallows a genuine decode
error inside a correctly-matched child as "try the next case," which would surface as a confusing
"unrecognized element" rather than the real failure.

## 3. Final Cut Pro AppleScript dictionary (READ-ONLY — constrains ScriptingBridge scope)

Source: `/Applications/Final Cut Pro Creator Studio.app/Contents/Resources/ProEditor.sdef`
(also readable via `sdef "/Applications/Final Cut Pro Creator Studio.app"`).

The entire dictionary is two suites and is **read-only**:

**Final Cut Pro Library suite** (`fxlm`), with
`<access-group identifier="com.apple.FinalCut.library.inspection" access="r"/>`:

| Class | Key properties | Elements |
| --- | --- | --- |
| `item` (base) | class, container, id, index, name, persistent ID, properties, essential properties | — |
| `library` | name, id, container, file (URL) | `event` (r) |
| `event` | name, id, container | `sequence` (r), `project` (r) |
| `project` | name, id, container, sequence | — |
| `sequence` | name, id, container, start time, duration, frame duration, timecode format | — |

Record type `media time` (`cmtm`) = `{value, timescale, epoch, flags}` — maps cleanly onto a
rational `FCPTime`.

Enumeration `timecode formats` (`tcfm`) = `unspecified | drop frame | non drop frame`. Note this
is a **third** state (`unspecified`) that the FCPXML `tcFormat` attribute (`DF|NDF`) does not have.

**Final Cut Pro Application suite** (`fxap`): a single `get` command, plus a class-extension adding
a read-only `library` element to `application`.

### Consequences

- There is **no** export, import, save, or mutation command. This independently corroborates the
  claim already in `AGENTS.md` that "Final Cut Pro's AppleScript dictionary is too limited to
  generate these samples reliably" and that FeaturePairs must be hand-exported.
- Every property is `access="r"`. A ScriptingBridge layer can only inspect.
- The only path to automating File → Export XML would be System Events UI scripting (keystrokes
  and menu-item clicking), which breaks across FCP versions and localizations. **Rejected** as a
  0.1.0 goal.

## 4. FCPXML 1.14 DTD reference notes

Path (Final Cut Pro 12.x installs as *Creator Studio*, and the DTDs live under
`Interchange.framework`, **not** `Flexo.framework`):

```
/Applications/Final Cut Pro Creator Studio.app/Contents/Frameworks/Interchange.framework/Versions/A/Resources/FCPXMLv1_14.dtd
```

Versions `FCPXMLv1_0` … `v1_14` are all present (15 files); 1.14 is the latest, 823 lines. An
identical set is mirrored in `/Applications/iMovie.app`.

### Facts that drive the type design

**Time** (DTD lines 6-9):
```
<!-- 'time' attributes are expressed as a rational number of seconds (e.g., "1001/30000s") -->
<!-- with a 64-bit numerator and 32-bit denominator. -->
<!-- Integer 'time' values, such as 5 seconds, may be expressed as whole numbers (e.g., '5s'). -->
```
→ `Int64` numerator, `Int32` denominator, and **two legal spellings for the same instant**. Hence
canonical-form preservation.

**Attribute entities** (lines 145-181) — the natural basis for shared Swift types:
- `%ao_attrs;` = `lane`, `offset`
- `%clip_attrs;` = `%ao_attrs;` + `name`, `start`, `duration` **#REQUIRED**, `enabled`
- `%clip_attrs_with_optional_duration;` — same but `duration` #IMPLIED; **only `asset-clip`**
- `%media_attrs;` = `format` (required IDREF), `duration`, `tcStart`, `tcFormat`

**Content models are ordered sequences.** Key line numbers to transcribe into `CodingKeys`:

| Element | DTD line | Note |
| --- | --- | --- |
| `sequence` | 435 | `(note?, spine, metadata?)` |
| `clip` | 476 | full ordered model |
| `asset-clip` | 516 | `note?, conform-rate?, timeMap?, %intrinsic-params;, (%anchor_item;)*, (%marker_item;)*, audio-channel-source*, (%video_filter_item;)*, filter-audio*, metadata?` |
| `title` | 566 | `param*, text*, text-style-def*` |
| `transition` | 613 | **only** `name`, `offset`, `duration` — no ref/lane/start/enabled |

`AssetClip.CodingKeys` today puts `keyword` before `note`, and `adjust-volume` before
`audio-channel-source` — both diverge from the DTD. The completeness gate cannot see this.

**Other structural facts worth not re-deriving:**
- `resources` = `(asset | effect | format | media | locator)*`. `locator` is a resource kind, and
  is **not modeled today**.
- `effect.uid` is `#REQUIRED`.
- `asset` = `(media-rep+, metadata?)` — `media-rep` is required and repeatable.
- `gap` does not use `%clip_attrs;`; it re-declares its own and has **no `lane`** (gaps are not
  anchorable).
- `spine` is itself in `%anchor_item;` — connected storylines are nested spines.
- `audition` = first child is the active one.
- `param` is recursive (`param*` inside `param`).
- `fcpxml` root is a three-way choice: `library`, bare `event*`, or bare event items — plus
  `import-options?` (a 1.14 addition, unmodeled).

**Enumerations:** `tcFormat (DF|NDF)`, `audioLayout (mono|stereo|surround)`,
`%audioHz; (32k|44.1k|48k|88.2k|96k|176.4k|192k)`, `srcEnable (all|audio|video)`,
`interp (smooth2|linear|smooth)`, `colorProcessing (standard|wide|wide-hdr)`,
`media-rep kind (original-media|proxy-media)`.

**Not enumerations** despite looking like it: `colorSpace`, `renderFormat`, roles, `fieldOrder` are
all `CDATA` with commented-out hints. Do not model these as closed enums.

### The `audioRate` trap

`asset.audioRate` is `"48000"` (plain integer Hz — see every fixture).
`sequence.audioRate` is `"48k"` (the `%audioHz;` enumeration).

Same attribute name, two different value spaces. `Asset.audioRate` must be `Int`; only
`Sequence`/`Multicam` use the `AudioRate` enum. Reversing this breaks all four TestData fixtures.

## 5. Repository layout (operational gotcha)

`/Users/leo/Documents/Projects/FCPKit` is a **bare repo + git-worktrees layout** managed by
[`git-trees`](https://github.com/brightdigit/git-trees). The project root contains only
`AGENTS.md` (git-trees boilerplate, *not* this project's real AGENTS.md) and `FCPKit.git/`.

- `git status` at the root fails: `fatal: this operation must be run in a work tree`.
- Read any branch's files without a checkout:
  `cd FCPKit.git && git show origin/v0.1.x:<path>`
- List files: `git ls-tree -r --name-only origin/v0.1.x`

  `git worktree add v0.1.x v0.1.x` from the project root).

same prototype squash as PR #1. `main` (`1f24cb2`) is still the 2-commit initial state and is the

**`main`'s README claims "Complete FCPXML Support" for 1.10+** — directly contradicted by ADR 0001

## 7. Other pre-existing issues noted

- **`AssetClipEditing.formatSeconds`** falls back to `"\(seconds)s"` for non-integral Doubles,
  emitting e.g. `13.333333333333334s` — not a legal rational time. Exact `FCPTime` arithmetic
  removes the function entirely; `setConstantSpeed(percent: 75, mediaDuration: "10s")` should be
  `40/3s`. Addressed by Step 2 / [#7](https://github.com/brightdigit/FCPKit/issues/7).
- **No CI, no lint, no format config.** `.github/` is absent on every branch; no `.swiftlint.yml`,
  no `.swift-format`, no `Mintfile`. The `--fail-if-total-exceeds 0` gate only ever runs manually.
  Filed as [#4](https://github.com/brightdigit/FCPKit/issues/4) (BrightDigit package scaffolding);
  now in v0.1.0 scope.
- **`Package.swift` sets no `swiftSettings`** — no `StrictConcurrency`, no upcoming features.
  Tools version 6.1 means Swift 6 language mode by default, but the model types are not declared
  `Sendable` (the `FCPXMLDiff` types are). May be folded into #4 or deferred.
- **Fixtures embed real local paths** (`file:///Users/leo/Movies/Current.fcpbundle/...`) and base64
  `<bookmark>` blobs. `AGENTS.md` acknowledges this and requires privacy review for new exports.
- **`FCPXMLParser` is a `class` with a stored `XMLDecoder`** but creates a fresh `XMLEncoder` per
  `encode` call — an asymmetry worth revisiting when `Sendable` is addressed.

## 8. Decisions taken in this session (with rationale)

| Question | Decision | Rationale |
| --- | --- | --- |
| Base branch | Evolve `v0.1.x`, no rewrite | 25 commits of working model + fixtures + diff harness; a rewrite discards proven round-trip evidence |
| Product emphasis | Create-from-scratch over edit-existing | Authoring valid new FCPXML is the acceptance bar; round-trip editing stays best-effort (ADR 0001) and must not expand 0.1.0 scope |
| Typing depth | Strong types in the Codable model itself | A DSL-only typing layer leaves the decode/edit path unchecked, which is where the `formatSeconds` bug lives |
| Plan breadth | **Full** eight-step plan (not narrow 0–3+6) | Create-first needs typed model + DSL + correct ordering in one working version |
| DSL scope | `FCPKitDSL`: SwiftUI-shaped `Document`; soft-promote shells; anchors via `.anchor` | Create-first A/D/F; hide FCP jargon on happy path |
| Resource IDs | Inline URL/`Asset`; dedupe by spec; manual id wins | No stored props on `Document`; XML registry still emitted |
| External media | `asset` + `media-rep/@src`; `locator` / `import-options` **out** | Fixtures and DTD already use `media-rep src` for file media; locator is a different resource kind; import-options are import knobs, not the cut |
| Spine encoding | Spike `items = ""`; else hand-written encode | Implementation detail; public `items: [SpineItem]` unchanged either way |
| Unknown enums | Pass-through decode default; opt-in **strict** throws | Matches ADR 0001 for importers; authors fail loud in the DSL; strict reserved for later validation |
| Spine migration | Clean break, **no** `assetClips` compatibility shims | Avoids shipping a deprecated surface; ~25 call sites are all in tests |
| ScriptingBridge | Read-only inspector, additive target | The sdef offers nothing else; UI-scripting export is too fragile |
| Scripting tcFormat | Separate `FCPScriptedTimecodeFormat` (+ `unspecified`), convertible ↔ `TCFormat` | Sdef has three states; FCPXML only DF/NDF — keep Codable DTD-faithful |
| XCTest → swift-testing | Defer to 0.1.1 | Migrating touches the same files as Step 3, destroying diff reviewability and bisectability |
| Products | `FCPKit` + `FCPKitDSL` + `FCPKitScripting` | Separate products; short `Document` name OK in DSL module |
| Multicam → DSL | Defer past 0.1.0 | Prove create path first; MediaTools stays on Codable |

### Explicitly rejected

- **Extending the completeness gate to be order-aware** instead of adding separate order tests —
  changing `Inventory`'s matching semantics risks masking genuine differences elsewhere in the
  diff engine.
- **Property wrappers for typed attributes** — they break `DynamicNodeEncoding`, which dispatches
  on the `CodingKey`, and force `@Wrapper` annotations at every use site.
- **Topologically sorting resources on emit** — real FCP output isn't sorted; the transitions
  fixture declares asset `r5` before its own format `r6`.
- **Reducing rational times to lowest terms** — the completeness gate compares attribute values as
  strings, so `22800/2400s` → `19/2s` would register as a changed attribute.
- **System Events UI scripting for FCP export** — fragile across versions and localizations.
- **Narrower 0.1.0 (Steps 0–3 + 6 only)** — deferred typing would leave create-path helpers on
  stringly times and split the “first working version” across two releases.
- **Modeling `locator` / `import-options` in 0.1.0** — not required to point at external media;
  no fixture uses them; revisit when generation needs import-behavior knobs.
- **Class-identity resource handles / `Resources { }` as primary API** — replaced by inline
  media + spec dedupe; keeps `Document` property-free.
- **`FCPUI` / `FCPKitUI` product names** — SwiftUI-*shaped* ≠ UI framework.
- **Smart anchor placement / full timeline graph layout** — 0.1.0 is spine pack + transition
  overlap only; anchors default offset 0.
- **Default `Gap.duration`** — gaps are intentional; must be set explicitly.

## 9. Resolved open questions (2026-07-28)

1. **`items = ""` + attributes on `Spine`?** Spike in Step 0; prefer that path if it works, else
   hand-written `MixedEitherSide` encode/decode. Not a product fork.
2. **Unknown enum values?** Pass through on decode by default; opt-in strict mode throws. DSL
   rejects invalid authoring values.
3. **Full vs narrow plan?** Full eight-step plan.
4. **`locator` / `import-options`?** Out of 0.1.0. External media = `asset` + `media-rep/@src`.
5. **Scripting `unspecified` tcFormat?** Separate scripting enum with bidirectional conversion to
   FCPXML `TCFormat?` (`unspecified` ↔ `nil`).

   `.constantSpeed(…)`; shapes not fully grilled.
2. **Time literals** — whether `10s` / `100/2400s` sugar exists in DSL or only `FCPTime(…)`.
3. **`RefClip` / `<media>` authoring** — needed for multicam-like B; not on A happy path.
4. **Transition overlap algorithm** — FCP rule stated; numeric write-up + tests still to author

5. **Preset catalog membership** — which `Format.*` / `Effect.*` ship in 0.1.0 (fixture-backed

6. **`URL` vs `filePath` / `String`** — spelling of media location arguments.
7. **Title `start` default** — fixtures often use `3600s`; whether DSL defaults that or requires
   explicit `.start`.
